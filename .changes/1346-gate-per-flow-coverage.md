### Fixed

- **`@reticlehq/server` — `reticle gate` and the `reticle watch` status line forgot every earlier replay as soon as a newer run recorded no flows.** Both read coverage from the single newest run, so one drive or export run with `flows: []` made every saved flow look unverified and the gate blocked a stop that had already been verified. Coverage is now read per flow, from each flow's newest result across runs, and a run with no flows neither supplies nor erases a result. A flow whose newest result is a failure still counts as uncovered, and so does an affected flow whose newest pass is older than the latest edit to a changed file. Closes [#1346](https://github.com/reticlehq/reticle/issues/1346).
